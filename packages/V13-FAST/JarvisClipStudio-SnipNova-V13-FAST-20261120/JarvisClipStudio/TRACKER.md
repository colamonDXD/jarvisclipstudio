## How to read this tracker

| Status | Meaning used here |
|---|---|
| COMPLETE | Implemented, connected to the real workflow, and supported by end-to-end or rendered proof appropriate to the requirement. |
| PARTIAL | Real functionality exists, but an important part of the requirement is missing, disconnected, unproven at the required depth, or contradicted by a live result. |
| MISSING | No working implementation was found in the audited code. A UI label, plan, profile field, or report claim is not enough. |
| NEEDS REAL-WORLD VALIDATION | Code and synthetic/integration tests or synthetic rendered proof exist, but the requirement has not yet been proven on real user content in the installed workflow. |
| IN DEVELOPMENT | Work exists on a named side branch or in a scheduled first operational cycle, but it is not merged, installed and proven as a completed workflow. |

### Evidence rules applied

- A feature is **not** COMPLETE merely because a panel, endpoint, profile field, or test fixture exists.
- Editing claims require exported-render evidence where the M2 lane produced it; synthetic proof is labelled synthetic.
- Where reports and code/live behaviour disagree, this tracker trusts the code and the live result and records the disagreement.
- “Live” below means the installed M2 build on Luffy's laptop, not Sanji's sandbox.
- The strongest recent live evidence is task `80fc89e3`: a roughly one-hour CORE Japan food/travel source completed **10 clips in about 40 minutes**, but auto-detect classified it as **Podcast & news**, and the exports used **blurred-pad layout rather than a tracked crop**.
